# OOM 内存压力与预测式分级冻结实验

在 Ubuntu VM 上同时运行 Krita 和三个后台任务，比较串行、无干预并发和预测式分级冻结。当前场景的后台是**栅格条带校正、内存列式表转换和批量数组评分**。三个任务分批增长并持有内存，便于观察前后台峰值叠加、冻结时机与完成时间。

## 当前调度策略

- **固定启动偏移**。以 Krita 首页就绪为 T0，数组、栅格和列式表在最近两轮的计划偏移分别为 64、72、73 秒。后台到点放行，首批完成后才可以冻结。Krita 受保护。
- **前台剩余峰值预留**。根据 Krita 最近确认的阶段，从历史总占用和匿名内存曲线查询剩余峰值，估算当前用量到峰值的额外需求。后台仍逐轮预测未来 2.5 秒的增长。
- **按余量试算冻融**。预计最低余量低于 500 MiB 时试算冻结。恢复候选加入预算后，预计最低余量须严格高于 756 MiB 并持续达标至少 0.5 秒。冻结暂停任务执行，已驻留的内存继续计账。

最近两轮峰值预留实验均完成四项任务，全局 OOM kill 增量为 0，最低可用内存分别为 636.14 MiB 和 414.51 MiB。500 MiB 用于预测决策，实测是否守线以整机 `MemAvailable` 为准。
