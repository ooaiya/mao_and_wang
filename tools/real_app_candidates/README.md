# Real GUI candidate observations

`capture.py` launches exactly one real GUI application in a dedicated systemd user service and observes cgroup v2 at a nominal 50 ms period. It never allocates a synthetic workload, sets memory.max/high, modifies Swap, or schedules concurrent workloads. Start the observer itself as a detached systemd user service so an interactive tool session ending cannot truncate data. The application service receives the active graphical session's display/authorization and isolated XDG config/cache paths.

All `--directory` and analysis `--output` arguments must refer to external TeamOOM data_collection/results directories, never the source repository. Assets, generated application projects, user configuration, screenshots and output artifacts belong outside Git. Never reuse an existing round directory.

Use the real GUI to submit computation. Append phase events with `--event` for app/window ready, task_submit, task_complete, output_verified and app_close. A cgroup ending does not prove computation succeeded. Verify artifacts and preserve failure evidence. Where an event is reconstructed from application logs/process census, document its source and uncertainty; never label an inferred timestamp as a direct GUI observation.

The observer records current/anon/file/peak, CPU, cgroup events/PSI, host available memory/Swap, and a one-second process census. It aborts only its own application service if MemAvailable falls below 2 GiB, an OOM kill occurs, or an observed child escapes. This host-availability abort is not a cgroup memory cap. Sampling quality is reported from actual intervals. Process RSS/PSS and state are recorded at the one-second process census using status/smaps_rollup; no image pixel enumeration occurs.

`analyze.py --data-root /home/mxt/TeamOOM/data_collection/app_candidates/BATCH --output /home/mxt/TeamOOM/results/app_candidates/BATCH/analysis` plots observed samples. It refuses an output inside a valid Git worktree. Metrics use the last confirmed GUI task submission through verified completion, excluding material loading. 95% platform is time above 95% of the observed computation peak; both total and longest contiguous durations are recorded. The simple log-ratio metric distance compares only the three supplied scalar targets; it is not a shape similarity score and does not substitute for manual growth/release review. No historical target CSV is fabricated. A missing completion or invalid_capture.md excludes a round from successful comparison.

Anon and file maxima may occur at different times. File pages already charged to another cgroup can be shared and not recharged on a warm read, so file-cache attribution depends on existing cache state. No global cache dropping is performed. Describe natural release before GUI close separately from closing release; automatic application exit can make these inseparable.

`gui.py --log /external/round/gui_actions.jsonl OP ARGS...` records supplied real-desktop actions with monotonic timestamps. Supported operations are click, ctrlclick, keys, press, text, focus, scroll and shot. It obtains display authorization from the existing systemd user graphical session. `pyautogui`, `wmctrl` and `gnome-screenshot` must already be installed. Coordinates require the recorded display geometry and application layout; inspect a screenshot before replaying a changed layout. It does not infer task success from a click.

`watch_workers.py --directory ROUND --workers nona enblend --artifact OUTPUT` records disappearance of observed computation children together with its polling uncertainty, requiring a nonempty artifact. It must start while a listed worker is still active. This is completion evidence, not output validation; separately confirm the native GUI reports success and fully decode/test the output. `watch_log.py --directory ROUND --success-text TEXT --count N` records a native log completion observation; the optional `--failure-text` ends observation on a reported error. Counts include all existing log entries, so an in-process retry must explicitly account for the earlier segment. Log buffering may add unbounded latency even when the polling interval is small.

A real task can use a native render-complete callback solely to save its actual result and timestamp completion. The callback must not submit computation. Configuration scripts may set normal scene, export, encoding and project parameters, but actual computation is submitted through the application's GUI. Preserve the configuration script and parameters outside Git with that run's evidence.

The analyzer preserves every attempted round, emits `candidate_summary.csv`, scalar target references, per-round total/anon/file plots and a common-scale comparison of completed tasks including up to 60 seconds of post-computation samples. A `timing_override.json` alongside raw samples can refine `task_submit_ns` or `task_complete_ns` using documented native log evidence; original phase events remain unchanged. Record source, timestamp precision and any reconstruction assumptions. The analyzer reports 10-to-90% growth, first 95% crossing, total and longest 95% occupancy, observed natural release, host minimum available memory, Swap activity and OOM counters. Scalar distance alone is not a match verdict. A successful reduced task in a capture containing an earlier failed segment is measured from its last confirmed submission; describe the earlier failures and reduced workload in the final report. Neither warm caches nor post-exit cache retention are a guaranteed reproducible baseline.

For new runs use `launch.py --application APP --directory /external/new_round -- GUI_COMMAND ...`. It refuses existing round directories and another active/deactivating `teamoom-app-*` unit. The standalone `capture.py` entry remains available for diagnosis; its caller is responsible for serial execution. The early batch used a host-local launch helper; all application commands are preserved in each round's `environment.json`.

`configure_blender.py` is passed to Blender with `--python`; set `TEAMOOM_BLENDER_CONFIG` to an external JSON containing `capture_directory`, `output`, `parameters_output`, `width`, `height`, and `samples`. It sets CPU path tracing, records actual parameters, and registers a result-saving completion callback. It never invokes render; use GUI F12 and record its event. Preserve linked scene assets in their original relative layout. The historical Agent327 scene used inherited branched path tracing; that failed attempt must not be described as the later Classroom path-tracing configuration.

Use `analyze.py ... --selection /external/selected_rounds.json` to choose one successful round per application for the six shared-scale comparisons; this JSON maps application names to round directory names. Every attempted round remains in `metrics.json`, `candidate_summary.csv` and its individual plot. Original raw CSV is never rewritten to add absent fields. Early capture schemas without per-cgroup Swap or swap-in/out counters report those metrics as unavailable, while retaining their measured host Swap usage. `app_exit_inferred` is an explicit bound from sampled task counts/cgroup removal, distinct from a directly observed GUI close. A disappearing cgroup does not mean all file-cache pages were freed. Post-exit zero memory samples are never invented. Failed tasks before a later GUI submission remain visible in the full lifecycle plot's negative-time region.

The final collector reuses the existing `基线并发/common/monitor.py` meminfo reader and reads vmstat once per sample. These reader/efficiency improvements do not launch, configure or integrate with the formal prediction/scheduling algorithms. The exact earlier collector source snapshot is retained externally with that batch's evidence.

Natural task cleanup can already have happened before a native completion callback or a worker-exit observation. Therefore `natural_release_gib` describes only completion-to-close change, while `peak_to_preclose_release_gib` also includes cleanup near computation completion. Neither quantity includes application-exit release. A retained GUI baseline and retained file cache must be stated separately. `time_to_peak_s` is the sampled global maximum; first `time_to90_s`, component crossings and 10-to-90% growth describe initial allocation separately. Absolute thresholds retain the GUI footprint. Additional increment metrics subtract the median observed one-second pre-submit baseline; never reconstruct a target trace.

For the second screening round, `configure_knime.py --installation KNIME --input HEADER_CSV --output RESULT_CSV --workflow NEW_WORKFLOW` generates an unexecuted native workflow using settings templates bundled in the official portable application. It reads no observation rows and never calls a KNIME executor. It explicitly selects Columnar Backend, quality-filters NOAA TMAX/TMIN/TAVG/PRCP records, preserves raw values and calculates their documented /10 units, sorts station/date/element and uses a native CSV Writer when Parquet is not installed. Open the workflow in KNIME GUI and confirm every node is configured/unexecuted before clicking Execute All. Linux installations whose Modern UI stalls in Chromium can use `-perspective org.knime.workbench.ui.ModellerPerspective` for the genuine classic GUI. JVM heap and Columnar off-heap cache are separate; neither is a cgroup cap. Do not force GC or reset nodes to create a release curve.

`watch_log.py --log-file NATIVE_LOG ...` can observe application-specific native logs. `watch_artifact.py --directory ROUND --artifact REAL_OUTPUT` observes a real output descriptor opening and closing inside the application cgroup and records its polling bounds. A nonempty artifact must have been observed open; starting this observer after writing finished cannot establish completion. A closed writer still needs GUI success and independent output verification. `verify_weather.py --input-gzip ORIGINAL_GZIP --output-csv KNIME_OUTPUT --report EXTERNAL_JSON` performs bounded-memory, full-row count/type/unit/conversion/order/fingerprint checks only after computation has completed.

`compare_rounds.py --manifest SELECTION_JSON --output EXTERNAL_ANALYSIS` compares `{"old": {app: capture_directory}, "new": {app: capture_directory}}` selections. All selected tasks must have a completion and later output verification. It emits actual-time plots, total/anonymous/file decompositions, and baseline-subtracted peak-increment normalization without time warping. Total and component peaks can differ in time. Natural observation ends at the earlier real close or last actual sample; tails shorter than ten seconds are explicitly censored. Raw samples and original phase events remain immutable. A documented `event_correction` can supersede an operator's mistaken interpretation by referring to its exact monotonic timestamp and corrected kind; unrelated failures and safety stops remain disqualifying. No target series, DTW or correlation is fabricated from scalar references.

For third-round Table candidates, `configure_duckdb.py` writes an unexecuted native `COPY` query for a prepared NOAA header CSV. Open it in DBeaver's DuckDB SQL editor; record actual JDBC/JVM/settings in external evidence. `watch_duckdb_profile.py` observes a complete native COPY JSON profile and a real output artifact; it never submits SQL. Native query latency and GUI-submit-to-completion observation are different timings.

`configure_hop.py --installation HOP --input HEADER_CSV --output RESULT_CSV --project NEW_PROJECT --config NEW_CONFIG` builds an unexecuted native Hop project from the official bundled templates. Open its `.hpl` in Hop GUI and use Run → local → Launch. The Calculator's arithmetic uses its left operand's runtime type: declaring a Number result does not prevent Integer division truncation. The pipeline therefore multiplies a native Number constant 0.1 on the left by preserved Integer DATA_VALUE. Run independent full-row validation before admitting any GUI-successful capture. Preserve failures and user interruptions in separate round directories with `invalid_capture.md`; never replace their raw samples.

QGIS native Aggregate runs can use `launch.py --application qgis`. The observer uses the same 50ms cgroup metrics and an additional 12GiB application safety stop (no cgroup limit); the established 2GiB host-availability guard remains. Configure an unexecuted native Processing dialog, then submit its Run button through the GUI. For independent QGIS-only captures, do not start Krita or another experiment application. Never call processing.run or qgis_process for the measured business operation. Keep algorithm progress/native-return events separate from independent output verification after the capture window.
