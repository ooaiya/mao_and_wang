# 磁盘和Swap只读核验

> 发布说明：本次依据用户随后“报告传到github的mxt_codex”的授权，仅发布Markdown报告。文中不提交/推送的限制描述此前只读诊断阶段。原始数据、CSV、日志、JSON与PNG留在VM。

|层次|实际值|结论|
|---|---|---|
|VMware虚拟块设备 /dev/sda|107374182400B = 100GiB|新容量已被内核识别|
|根分区 /dev/sda3|85358280704B，约79.50GiB|没有扩展到100GiB|
|根ext4，df口径总容量|83423059968B，约77.69GiB|仍为原文件系统容量|
|根文件系统可用|12283449344B，约11.44GiB（当前快照）|不能将20GiB新增盘尾空间算作已可用|
|分区外盘尾|最后分区End167770111，磁盘209715200扇区，扇区512B，约20GiB未纳入分区|包含GPT尾部开销；未操作分区|
|Swap|/swapfile，2147479552B，当前使用0|文件型Swap，位于 /dev/sda3 根文件系统，未自动变大|

fdisk -l提示GPT PMBR size mismatch (167772159 != 209715199)。这是只读检查输出；没有进入写入模式、没有修改GPT、没有growpart/resize2fs或改Swap。df显示的文件系统可用容量与分区字节口径不同，不能将文件系统元数据/保留块差异当作全都未分配。

扩容已完成虚拟磁盘这一层，分区和文件系统尚未使用新增空间，因此“100GB已全部可用”为否。未来如单独授权完成分区/文件系统扩展，可增加根目录可用空间，理论上也给未来Swap文件扩展提供空间；本轮没有执行这些操作。

此次磁盘扩容发生在故障之后，不会逆转历史PSI事件，也不会增加VM物理内存或现有Swap。故障时磁盘预检约11.57GiB可用，没有磁盘耗尽证据；不能把增加磁盘当作已解决内存回收压力。

原始证据：current/lsblk.txt、partitions.txt、df.txt、findmnt.txt、swapon.txt、swaps.txt。
